2. Installed jspdf: `cd /home/z/my-project && bun add jspdf` → resolved
   jspdf@4.2.1 (server build at `node_modules/jspdf/dist/jspdf.node.min.js`,
   selected automatically via the `exports` "node" condition).
3. Created `/home/z/my-project/src/lib/pdf/resume.ts` exporting
   `generateResumePdf(resumeId: string): Promise<{ buffer: Buffer; filename: string }>`:
   - Loads Resume + bullets (ordered by orderIndex) + Job (for title) + Student
     (with User + Education) in one Prisma findUnique.
   - Aggregates every `evidenceIds[]` and `skillIds[]` referenced by any bullet
     and batch-fetches the Evidence and Skill rows (skipped entirely when empty).
   - Uses `jsPDF` configured for US-Letter, points, compress=true, with document
     metadata (title/subject/author/creator).
   - Layout helpers: `ensureSpace()`, `drawRule()`, `renderSectionHeading()`,
     `renderParagraph()`, `renderBullet()` with hanging indent, multi-line wrap
     via `splitTextToSize`, automatic page break when y > pageHeight - margin
     - footer band.
   - Sections rendered (in this order): Header (name + contact line), Professional
     Summary, Education (uses structured Education rows when present), Technical
     Skills (comma-separated skill displayNames aggregated from `skillIds` on
     skills-section bullets — fetched via Skill rows), Projects (with "Evidence:
     <title> [status]" sub-lines for each linked evidence), Experience &
     Achievements (bullets with section 'experience' or 'certifications',
     same evidence sub-lines).
   - For bullets with `claimStatus === 'UNSUPPORTED'`, strips any pre-existing
     inline "[Unverified]" marker from the text (so the marker is consistent) and
     appends " (Unverified)" rendered in muted-red. Pure server-side — no
     `window` / `document` access.
   - Footer drawn on every page (loop with `setPage`): "Generated by Placement
     Hub • Evidence-backed resume • Algorithm v1.0" + "Page N of M" + thin rule.
   - Output via `doc.output('arraybuffer')` → `Buffer.from(arrayBuffer)`.
   - Filename: `<slugified studentName>-resume-<slugified jobTitle OR "v" + version>.pdf`.
4. Rewrote `/home/z/my-project/src/app/api/resumes/[id]/pdf/route.ts`:

   - Auth: `requireUser(req)` then allow if `role === OFFICER` or `ADMIN`
     (any resume). For STUDENT role, fetch resume.student.userId and compare to
     caller's user.id (must be the owner). Recruiters and any other role get 403.

     `Content-Length` and `Cache-Control: no-store`.
