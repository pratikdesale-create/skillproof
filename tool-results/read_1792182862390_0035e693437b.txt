     1→# MASTER DEVELOPMENT PROMPT — PS6: PLACEMENT HUB
     2→## Build a Complete, Production-Structured, Full-Stack Evidence-Based Campus Placement Platform
     3→
     4→### 1. ROLE AND MISSION
     5→
     6→Act as a senior full-stack software engineer, solution architect, UI/UX designer, database engineer, AI engineer and application security specialist.
     7→
     8→Build a complete, functional, responsive web application called **Placement Hub**.
     9→
    10→This application addresses the following problem:
    11→
    12→College students often apply to many jobs using generic resumes and unverified skill claims. Placement officers receive openings through multiple sources, struggle to track candidates and duplicate postings, and lack a reliable way to rank students. Employers need shortlists based on demonstrable skills rather than unsupported resume statements.
    13→
    14→Your mission is to implement a unified evidence-based placement management platform that connects:
    15→
    16→1. Employer job requirements.
    17→2. Students' actual skills and supporting evidence.
    18→3. Explainable job-fit scoring and skill-gap analysis.
    19→4. Truthful, job-specific resume generation.
    20→5. Centralized application tracking.
    21→6. Batch-wide student ranking.
    22→7. Recruiter shortlisting and optional alumni and interview-question features.
    23→
    24→**Core product principle: Every skill claim, match recommendation and generated resume bullet must be traceable to supporting evidence or explicitly identified as unverified.**
    25→
    26→Do not build a generic job board with decorative AI features. Implement the actual business logic behind the product.

   341→

   344→## Supported evidence types

   347→
   348→- Assessment results.

   360→
   361→- Evidence ID.
   362→- Student ID.
   363→- Evidence type.
   364→- Relevant skill IDs.
   365→- Title and description.
   366→- Source URL or secure file reference.
   367→- Date submitted.
   368→- Issuing organization or assessor when relevant.
   369→- Assessment score and maximum score when applicable.
   370→- Reviewer ID.

   374→- Provenance information.

   540→# 10. JOB-FIT SCORING ENGINE
   541→
   542→Implement an explainable and independently testable matching service.
   543→
   544→The system should compare job requirements with the student's evidence-backed profile.
   545→
   546→## Initial scoring formula
   547→
   548→For a given job and student, calculate:
   549→
   550→Fit score = 100 × (sum of requirement weight × evidence match value) / (sum of requirement weights)
   551→
   552→Use the following initial configurable weights:
   553→
   554→- Required skill: weight 4.
   555→- Preferred skill: weight 1.
   556→
   557→Each requirement has an evidence match value between 0 and 1.
   558→
   559→An example policy:
   560→
   561→- No submitted supporting evidence: 0.
   562→- Relevant evidence submitted but not yet reviewed: partial provisional credit.
   563→- Relevant evidence verified: credit according to the configured verification and relevance rules.
   564→- Rejected or irrelevant evidence: no positive credit from that evidence.
   565→
   566→These values are configurable policy examples, not universal measures of ability.
   567→
   568→When multiple evidence items support a skill, deduplicate the underlying skill contribution so one student cannot inflate their score merely by attaching numerous similar links.
   569→
   570→Keep the following concepts separate:
   571→
   572→- Skill claimed.
   573→- Evidence submitted.
   574→- Evidence verification status.
   575→- Evidence relevance.
   576→- Assessment result.
   577→- Match score for a job.
   578→
   579→## Required skill handling
   580→
   581→Show required-skill coverage separately from the overall fit score.
   582→
   583→If a student lacks evidence for a critical required skill, explicitly flag the gap.
   584→
   585→Do not automatically describe a missing skill as a confirmed inability to perform the work.
   586→
   587→Allow the placement officer to configure whether certain eligibility requirements are hard filters or review flags. Do not silently apply academic, demographic or other discriminatory rules.
   588→
   589→## Explainability
   590→
   591→For every student-job pair, return:
   592→
   593→- Overall fit score.
   594→- Required-skill coverage.
   595→- Preferred-skill coverage.
   596→- Matching skills.
   597→- Missing or insufficiently supported skills.
   598→- Supporting evidence references.
   599→- Evidence verification states.
   600→- Explanation of the main factors affecting the score.
   601→- Recommendation for closing relevant skill gaps.
   602→
   603→Store the scoring algorithm version and the relevant inputs so results can be reproduced or audited.
   604→
   605→Build unit tests for correct scoring, missing evidence, rejected evidence, duplicate evidence and edge cases.

   713→# 13. APPLICATION TRACKING PIPELINE
   714→
   715→Implement a normalized application model that tracks the student-job relationship.
   716→
   717→Support configurable stages such as:
   718→
   719→- Applied.
   720→- Under review.
   721→- Shortlisted.
   722→- Assessment.
   723→- Interview.
   724→- Offer.
   725→- Rejected.
   726→- Withdrawn.

   729→
   730→Do not force every application into the same linear sequence. Record valid transitions and allow authorized role-specific changes.
   731→
   732→Each application record should have:
   733→
